## 充值之前，先分清你在付哪笔钱

很多人卡在这一步，是因为把两套账混在了一起。

**Claude 订阅会员和 API 余额是分开的。**Pro 订阅（20 美元/月）附带的额度用在 Claude 网页版、官方应用和 Claude Code 的订阅计费线上，它不等于 API 账户里的余额。你在网页版订了 Pro，去调 API 时余额照样是零，这是官方计费体系里的两个独立入口。

API 走的是 Anthropic 开发者控制台（Console）里的预付额度模式：先买额度，调用时按 token 用量扣，扣完就得再充。几条官方规则值得先记住：

- 额度购买一年后过期，过期日期无法延长，所有充值都不可退款；
- 失败的请求不计费，但请求进行到一半客户端断线或超时，这笔照扣；
- 余额归零后，不充值就无法继续调用 API。

顺带一提：如果你最终目的是在电脑命令行里用 Claude Code，它默认消耗的正是 API 额度。所以「给 Claude API 充值」这件事，本质上也决定了你能不能用上 CLI 版的完整能力——这也是为什么订阅那条线的省钱攻略帮不到重度开发者。

官方计费只有两种模式，个人和小团队接触到的基本都是第一种：

### 路径二：第三方 API 中转（微信直充，但有代价）

国内有一些 API 中转平台，支持微信、支付宝直接充值，部分还提供国内加速节点。用法是把代码或工具里的 API 地址改成中转平台的接口地址，密钥换成平台发的 Key，其余调用逻辑基本不用动。

它的好处是门槛低：不用开卡、不碰官方收银台，注册认证后就能用，跑测试、做个人小工具很方便。

代价也明确：你的所有请求内容都会经过中转平台。用户数据、商业机密这类敏感信息，别往第三方链路上传。比较稳的用法是测试环境用中转，正式业务还是接官方 API——数据合规这一关，中转方案目前给不了答案。

### 路径三：找人代充（API 这条线基本劝退）

订阅 Pro 可以走激活码代充：你拿到激活码，自己在官方页面激活，全程不用交账号密码，风险可控。但 API 是预充值绑账号模式，没有「激活码」这种东西可买。所谓 API 代充，往往意味着把账号交给别人操作，账号安全完全取决于对方——这种风险无论省多少钱都不值得承担。真到这一步，不如回头选路径一。

## 充值成功但调用失败？先看错误再掏钱

余额不足、速率限制和模型权限是三件不同的事，别一调不通就继续充值。先看 API 返回的实际错误：

- **401 认证失败**：检查 Key 是否复制完整、有没有被删除或过期，控制台里能看到密钥状态；
- **429 频率或额度问题**：可能是余额用完，也可能触发了速率限制——余额充足还报这个错，基本就是后者；
- **504 超时**：换网络环境，或把大段内容分批传入，减少单次请求的 token 量；
- **充值到账但仍然调不通**：确认用的是正确组织和项目下的 Key，账单状态是否已生效，目标模型是否有调用权限。

另外，充更多钱不会自动提高调用速度。速率限制、账户等级和余额是分开管理的，具体以官方规则为准。应用端也建议自己设好用户配额、并发数和重试上限，防止程序出bug时陷入错误循环，一晚上把余额烧光。

密钥保管也别偷懒：别把 Key 硬编码进代码仓库，用环境变量读取；隔几个月在控制台换一次新 Key，旧 Key 及时撤销。

## 几个常见问题

**用微信充值的虚拟卡付款，账号会被封吗？**
走官方渠道自己绑卡自己充值，和持有一张海外信用卡没有本质区别，不存在代登录那种风险。真正危险的操作是把账号密码或验证码交给别人。

**最低要充多少？**
Console 单次充值最低 5 美元起，按实际 token 消耗扣费，控制台会实时显示用量。

**Pro 会员包含 API 余额吗？**
不包含，两套独立的计费系统。要用 API 就得在 Console 单独购买额度。

**充进去的额度能退吗？**
不能。购买一年后过期，过期日期也没法延长，这是官方明文条款。充值前先估算自己的月均用量再决定金额。

**额度用完了会怎样？**
在充入新额度之前，API 和 playground 都无法继续调用，已有的 Key 不会失效，充完就能接着用。

**为什么 Anthropic 不直接支持人民币？**
Anthropic 是美国公司，全球业务用美元结算，没有在国内开通本地支付通道。这不是针对谁，而是大多数海外 AI 产品的通病。
